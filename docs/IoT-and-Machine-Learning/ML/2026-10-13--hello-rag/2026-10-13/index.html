Vector Database​

To get started I will try ChromaDB to store my embeddings. And I was right - the embedding creation is now fully automatic. I just need to point the Chroma function to my PDF asset chunks and to a db location and it database is automatically created containing the embeddings:

from pathlib import Path

asset_path = Path("src/rag_intro/assets/IMX415-AAQR_Flyer.pdf")
asset_path.parent.mkdir(parents=True, exist_ok=True)

db_path = Path("src/rag_intro/db/")
db_path.parent.mkdir(parents=True, exist_ok=True)

RAG Agents​

I previously already build a LangChain ReAct agent based on a RAG loop from an SQL database. Let's do the same thing now with the ChromaDB connection - I will also add a mocked SQL query for alarm events so that I will have 2 tools to work with and can test the model selecting the correct one based on the user prompt:

from pathlib import Path

from langchain.agents import create_agent
from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain.tools import tool

client = ChatOpenAI(
    model="qwen3.8:latest",
    temperature=0.6,
    top_p=0.95,
    base_url="http://localhost:11434/v1",
    api_key="ollama",
)

# --- 1. Vector DB (RAG over your Chroma embeddings) -------------------------

db_path = Path(__file__).resolve().parent.parent / "rag-intro" / "db"
db_path.parent.mkdir(parents=True, exist_ok=True)

embed_model = OpenAIEmbeddings(
    model="qwen3-embedding:0.6b",
    base_url="http://localhost:11434/v1",
    api_key="ollama",
    check_embedding_ctx_length=False
)

db_con = Chroma(persist_directory=str(db_path), embedding_function=embed_model)


# --- 2. Tools ----------------------------------------------------------------

@tool
def license_plate_list(plate: str) -> str:
    '''Use this tool when you need to answer a question about when a
    specified registration number / license plate was last detected.
    Do NOT use it for questions about camera or sensor specifications.
    Args:
        plate (str): The license plate number of the car to look up.
    Returns:
        str: A string containing information of the corresponding alarm
        event - containing the time stamp of the event and the alarm trigger.
    '''
    # Hard-coded info - simulating SQL retrieved data
    records = [{
        "plate": "K:FG:123",
        "timestamp": "Wed Oct 14 08:17:05 PM HKT 2026",
        "trigger": "Alarm triggered by Motion area 1"
    },{
        "plate": "K:SX:712",
        "timestamp": "Wed Oct 14 12:01:45 PM HKT 2026",
        "trigger": "Alarm triggered by Motion area 3"
    }]

    for record in records:
        if record["plate"].lower() == plate.lower():
            return (
                f"(License plate {record['plate']} last seen at "
                f"{record['timestamp']}. {record['trigger']}.)"
            )

    known = ", ".join(r["plate"] for r in records)
    return (
        f"(License plate {plate} was not found in recent alarm events. "
        f"Plates on file: {known}.)"
    )


@tool
def sensor_spec_search(query: str) -> str:
    '''Use this tool when a question is asked about the technical
    specifications of the SONY IMX415-AAQR STARVIS sensor, e.g. its size
    or diagonal, resolution, readout, frame rate, sensitivity, or lens
    mount. It searches the sensor datasheet in the Chroma vector database.
    Do NOT use it for questions about license plates or alarm events.
    Args:
        query (str): The specification question or the property the user
        is asking about.
    Returns:
        str: The relevant datasheet passages retrieved from the vector DB.
    '''
    chunks = db_con.similarity_search(query, k=3)

    if not chunks:
        return "(No relevant passages found in the sensor datasheet database.)"

    passages = [
        f"Passage {i + 1}:\n{chunk.page_content}"
        for i, chunk in enumerate(chunks)
    ]
    return "(Datasheet passages retrieved from the vector DB:\n\n" + "\n\n".join(passages) + ")"


toolkit = [
    license_plate_list,
    sensor_spec_search,
]


# --- 3. Agent loop: execute tool calls -----------------------------

agent = create_agent(client, toolkit)


def ask(question: str) -> str:
    result = agent.invoke({"messages": [("user", question)]})

    print("\nModel Response:")
    print(result["messages"][-1].content)
    print("=" * 72)
    return result["messages"][-1].content


print("Q1 (routes to Chroma tool): What is the diagonal of the SONY IMX415-AAQR STARVIS sensor?\n")
ask("What is the diagonal of the SONY IMX415-AAQR STARVIS sensor?")

print("\nQ2 (routes to plate tool): When was the car with license plate K:SX:712 last seen?\n")
ask("When was the car with license plate K:SX:712 last seen?")

And both queries are routed to the correct tool and return the correct answer - awesome!

Improving the RAG Data Quality with Symantic Chunking​

The data retrieved from ChromaDB was often cut off / incomplete because of the fixed chunking. The solution is to have the process check which part of the text belongs together and should be retrieved in an single chunk. LangChain just added a text splitter to it's experimental package that says it is doing just that. So let's rebuild the database using the semantic splitter:

from pathlib import Path

from langchain_chroma import Chroma
from langchain_community.document_loaders import PyPDFLoader
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings


asset_path = Path(__file__).resolve().parent.parent / "rag_intro" / "assets"
asset_path.parent.mkdir(parents=True, exist_ok=True)

db_path = Path(__file__).resolve().parent.parent / "rag_intro" / "db"
db_path.parent.mkdir(parents=True, exist_ok=True)

# Load the text source from pdf file

loader = PyPDFLoader(str(asset_path) + "/IMX415-AAQR_Flyer.pdf")
docs = loader.load()
full_text = "\n".join([page.page_content for page in docs]) # the pages have to be merged into a single string

# Create vector embeddings from pages

embed_model = OpenAIEmbeddings(
    model="qwen3-embedding:0.6b",
    base_url="http://localhost:11434/v1",
    api_key="ollama",
    check_embedding_ctx_length=False
)

splitter = SemanticChunker(embed_model, breakpoint_threshold_type="percentile", breakpoint_threshold_amount=0.6)
semantic_chunks = splitter.create_documents([full_text])

# # DEBUG
# print(len(semantic_chunks)) # returns 19 -> much larger chunks now
# print(semantic_chunks[0])
# # -> The IMX415-AAQR is a diagonal 6.4 mm (Type 1/2.8) CMOS active pixel type solid-state image sensor with a square pixel array and 8.46 M effective pixels. This chip operates with analog 2.9 V, digital 1.1 V, and interface 1.8 V triple power supply, and has low power consumption.

# Create db with embeddings

db = Chroma.from_documents(semantic_chunks, embed_model, persist_directory=str(db_path))

Agent Memory​

Having your agent recall the current conversation. The easiest way to save the information in a variable and simply pass it back to the agent for every call that requires the context:

agent = create_agent(client, toolkit)

agent_memory = []

def ask(question: str) -> str:
    result = agent.invoke({"messages": [("user", question)]})
    message = result["messages"][-1].content

    agent_memory.append(message)

    print("\nModel Response:")
    print(message)
    print("=" * 72)
    return message


print("Q1 (routes to Chroma tool): What is the diagonal of the SONY IMX415-AAQR STARVIS sensor?\n")
ask("What is the diagonal of the SONY IMX415-AAQR STARVIS sensor?")

print("\nQ2 (routes to plate tool): When was the car with license plate K:SX:712 last seen?\n")
ask("When was the car with license plate K:SX:712 last seen?")

print("\nQ3 (agent memory): What was the license plate of the car that triggered an alarm on Wednesday, October 14, 2026, at 12:01:45 PM HKT?\n")
ask(f"What was the license plate of the car that triggered an alarm on Wednesday, October 14, 2026, at 12:01:45 PM HKT? You can refer to the previous conversation: {agent_memory}")

print("\nQ4 (agent memory): Can you summarize the conversation?\n")
ask(" ".join(str(memory) for memory in agent_memory))
